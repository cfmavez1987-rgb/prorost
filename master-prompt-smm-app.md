# Мастер-промт: SMM-помощник — мобильное приложение + рекламный сайт

Скопируйте текст ниже целиком и используйте как промт для Claude (или другой AI-модели) при разработке проекта.

---

## Роль и контекст

Ты выступаешь как full-stack разработчик и продуктовый дизайнер. Нужно создать два связанных, но независимых артефакта для продукта **«SMM-помощник»** — мобильного приложения для ведения соцсетей с AI-генерацией постов:

1. **Мобильное приложение** (React Native / Expo, TypeScript) — рабочий продукт для пользователей.
2. **Рекламный сайт-лендинг** (HTML/CSS/JS, одна страница) — промо-страница для привлечения пользователей и скачивания приложения.

Backend уже существует отдельно (Node.js + Express + PostgreSQL + YandexGPT) и предоставляет REST API. Мобильное приложение должно быть **полноценным клиентом этого API** — то есть работать через сервер, а не автономно.

---

## Часть 1. Мобильное приложение

### Технологии
- React Native через Expo, TypeScript.
- Навигация: `@react-navigation` (stack, при необходимости — bottom tabs).
- Хранение токенов: `@react-native-async-storage/async-storage`.
- Графики: `react-native-chart-kit` или `victory-native`.
- Работа с backend только через REST API (JWT в заголовке `Authorization: Bearer`).

### Функциональность (обязательный минимум)
1. **Авторизация** — вход и регистрация по email/паролю, хранение JWT-токена, автоматический редирект в приложение при активной сессии.
2. **Лента постов** — список постов пользователя со статусами (черновик / запланирован / опубликован / ошибка), pull-to-refresh, переход к созданию нового поста.
3. **Создание поста с AI-генерацией** — поле «о чём пост» + выбор тона → кнопка генерации текста через backend (`/ai/generate`, YandexGPT) → редактируемый результат → сохранение как черновик.
4. **Планирование публикации** — выбор даты/времени, отправка на `/posts/:id/schedule`.
5. **Аналитика** — график динамики охватов/вовлечённости по посту или аккаунту (`/analytics/*`), ключевые метрики (подписчики, engagement rate) в виде карточек.
6. **Подключение соц. аккаунтов** — экран со списком подключённых аккаунтов (VK/Telegram/Instagram) и запуск OAuth-подключения нового.

### Нефункциональные требования
- Понятные состояния загрузки и ошибок (не «тихие» падения).
- Формы с валидацией на клиенте перед отправкой на сервер.
- Код структурирован по папкам: `screens/`, `api/`, `context/`, `components/`.
- Все тексты интерфейса — на русском языке, в активном залоге, без канцелярита.

### Формат сдачи
- Полный исходный код проекта (все экраны, навигация, API-клиент).
- `README.md` с инструкцией запуска через Expo и списком того, что осталось доделать.

## Часть 2. Рекламный сайт (лендинг)

### Технологии
- Один HTML-файл, чистые CSS и JS (без сборщиков), шрифты — через Google Fonts.
- Полностью адаптивный (мобильная версия обязательна).

### Задача страницы
Продать идею продукта человеку, который устал вручную вести соцсети: показать, что приложение экономит время (AI-генерация), снимает тревогу за расписание (автопубликация) и даёт понятную картину результата (аналитика). Призыв к действию — скачать приложение (App Store / Google Play).

### Структура (обязательные блоки)
1. **Hero** — сильный заголовок с сутью продукта, короткое пояснение, кнопки CTA, визуальный акцент (иллюстрация/анимация, а не шаблонный дашборд-скриншот).
2. **Соц. доказательство** — блок с типами клиентов или (если есть) реальными логотипами/отзывами.
3. **Возможности** — 4–6 карточек с ключевыми функциями (AI-генерация, расписание, аналитика, несколько площадок).
4. **Как это работает** — пошаговый флоу от идеи до результата (3–5 шагов).
5. **Результаты/цифры** — конкретные метрики эффекта от использования продукта.
6. **Отзыв клиента** — один развёрнутый цитируемый кейс.
7. **Финальный CTA** — повтор призыва скачать приложение.
8. **Футер** — ссылки, копирайт.

### Требования к дизайну
- Не использовать шаблонные AI-паттерны «в лоб»: ни (а) бежевый фон + бордовый акцент под Claude, ни (б) чёрный фон + один кислотный акцент, ни (в) газетную вёрстку с тонкими линиями — если только это не единственный уместный вариант для данного бренда.
- Придумать свою цветовую и типографическую систему (роль дисплей-шрифта, роль текстового шрифта), обосновать выбор через смысл продукта (например: рост охватов = органическая метафора роста, а не дефолтный SaaS-дашборд).
- Выбрать один «сигнатурный» визуальный элемент, который делает страницу узнаваемой, и не размывать внимание на десяток эффектов.
- Соблюдать доступность: видимый фокус на интерактивных элементах, уважение `prefers-reduced-motion`.
- Копирайтинг — от лица пользователя, конкретный, без пустых маркетинговых обещаний.

### Формат сдачи
- Один самодостаточный `index.html` файл, готовый к открытию в браузере.

## Важное ограничение

Backend в рамках этого промта **не разрабатывается заново** — он считается готовым и доступным по REST API (эндпоинты авторизации, постов, AI-генерации, аналитики). Если контракт API неизвестен, перед началом работы уточни или зафиксируй предполагаемую структуру эндпоинтов и придерживайся её во всех запросах из мобильного приложения.
